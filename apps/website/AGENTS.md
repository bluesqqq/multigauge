# Flask Website Guide

This file refines the repository guide for `apps/website/`.

## Application boundaries

- This is a Python Flask/Jinja application. Route blueprints live in `routes/`, SQLAlchemy models in `models/`, shared backend logic in `services/`, HTML in `templates/`, and directly served JS/CSS/images/data in `static/`.
- There is no Node package manifest, frontend bundler, or configured npm script. Preserve the existing browser-module/static-asset structure unless deliberately introducing a justified dependency and its owning manifest.
- Do not reimplement renderer/editor behavior in Flask or site JavaScript. Consume the WebAssembly bundle generated by `ports/web/` through `/multigauge-web/...`.
- Keep uploaded package validation aligned with `docs/schemas/package.schema.json`, `docs/storage.md`, core import/export behavior, example packages, and workshop/editor consumers. Validate before persistence and never derive storage paths from untrusted client paths.

## Environment and data

- Python dependencies are listed in `requirements.txt`; no Python version is declared for this app. The production command in `render.yaml` is `gunicorn app:app`.
- `SECRET_KEY` and `STRIPE_KEY` are required at import/startup. `DATABASE_URL` is optional and defaults to the ignored instance SQLite database. Firmware lookup may use `MULTIGAUGE_RELEASE_REPOSITORY` or `GITHUB_REPOSITORY`, plus optional `GITHUB_TOKEN`/`GITHUB_API_TOKEN`. Development seeding additionally requires `ADMIN_EMAIL` and `ADMIN_PASSWORD`.
- Never commit `.env`, credentials, tokens, or local `instance/` database state. Use dummy/non-production values for local checks.
- `requirements.txt` currently does not list the imported `stripe` package. Do not assume a clean requirements-only environment can start the app; report this manifest gap rather than hiding it with an undeclared local install.

## Commands and generated assets

From `apps/website/`, the conventional dependency install and local entry point are:

```powershell
python -m pip install -r requirements.txt
python app.py
```

Production uses:

```powershell
gunicorn app:app
```

The app creates tables during import. `scripts/create_db.py`, `scripts/seed_db.py`, and `scripts/import_packages.py` mutate local database data; run them only when that mutation is part of the task and with the required environment configured.

- `static/multigauge-web/` is generated by the root `publish-web-assets` script from `ports/web/dist/`; do not hand-edit it.
- `static/firmware/multigauge/manifest.json` is generated by `scripts/sync-firmware-manifest.ps1`; refresh it through that script when release-manifest data is intentionally updated.
- No automated website test, lint, format, or build command is configured. Verify backend changes with an import/startup or targeted route/service check using safe local environment values; verify template/static changes in a browser. State what was not exercised.
